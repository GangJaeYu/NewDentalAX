# PRD — 치과 원내 업무 AX 웹 서비스

> 상태: **v1.0 사용자 확인 완료 (2026-11-02)** — 범위·우선순위(P0/P1/P2), NFR 수치, 디자인(docs/DESIGN.md) 확정
> 입력: `docs/IDEA.md`(아이디어 합의), 사용자 원문 요구서(0~14절), PRD 단계 질의응답
> 다음 단계: 디자인 확정 → `trd-generator`

## 1. 목적

일반적인 치과 병의원(직원 5~20명)이 진료 외 업무를 원내 웹 서비스 하나로 모으고 AI로 줄이게 한다. 대상 업무는 데스크 소통, 재고·발주, 서류, 근무, 시설·법정 점검, 지출이다. 서비스는 환자 정보를 저장하지 않고 AI로 보내지도 않는다. 원내 Windows PC 한 대가 서버가 되고, 원내 네트워크의 브라우저로 접속한다.

## 2. 사용자와 역할

| 역할 | 대표 사용자 | 주 사용 상황 |
|---|---|---|
| 원장·관리자(`admin`) | 원장, 지정 관리자 | 승인, 지출·지표 확인, 설정·백업·AI 예산 관리 |
| 실장(`manager`) | 데스크 실장 | 공지, 발주, 거래처, 연차 승인, 문서 작성 |
| 직원(`staff`) | 치과위생사, 간호조무사, 데스크 직원 | 체크리스트, 입출고 기록, 점검 기록, 연차 신청, AI 문서·스크립트 |

|---|---|---|---|

| 연차 승인, 근무표 편집, 발주서 작성, 거래처 관리, 지출 기록·월간 요약, 공지 작성·고정 | ✅ | ✅ | ❌ |

## 3. 핵심 흐름 (IDEA 2절 연결)

- **US-001** 실장은 아침에 대시보드 한 화면에서 오늘 할 일, 재고 경고, 다가오는 점검, 공지를 확인하고 오픈 체크리스트를 처리한다.
- **US-002** 직원은 재료 출고를 2번 클릭 안에 기록하고, 실장은 부족 품목의 거래처별 발주서를 자동으로 받아 인쇄·PDF로 저장한다.
- **US-003** 실장은 거래명세서 사진을 올려 AI가 읽은 입고 초안을 확인한 뒤 저장한다. 이때 단가 변동이 자동으로 기록된다.
- **US-004** 직원은 문서 종류와 요점만 입력해 인쇄용 문서 초안을 받는다. 개인정보는 자동으로 막히거나 가려진다.
- **US-005** 직원은 원내 매뉴얼을 근거로 AI 도우미에게 묻고, 답과 근거 문서를 함께 받는다.
- **US-006** 직원이 연차를 신청하고 실장·원장이 승인하면 근무표와 알림에 반영된다.
- **US-007** 원장은 AI 사용량·비용과 예산 상태를 보고, 공급자·모델·키·한도를 바꾼다.

## 4. 범위와 우선순위

- **P0 (필수, MVP)**: 반드시 완성한다. 공통 기반, 관리, AI 기반, A·B·C·G, E의 법정 일정, D의 연차
- **P1 (첫 버전 포함, MVP 이후)**: 사용자 지시("확장까지 전부")에 따라 Loop 안에서 완성한다. D·E·F의 나머지와 IDEA에서 고른 추가 후보 4개
- **P2 (나중)**: 바코드·QR 출고, AI 근무표 자동 배정 제안, 회의 음성 → 회의록. 24시간 상한 안에서 P0·P1 완료 후 시간이 남으면 진행한다.
- **제외**: 예약·환자 관리, 보험청구, 전자차트 연동, 기공 의뢰서, 급여 계산, 직원 평가, 문자·알림톡 실제 발송, HWP 직접 변환, 인터넷 외부 공개 배포, 여러 지점 운영

## 5. 기능 요구 (FR)

수용 기준(AC)은 "행동 → 확인할 결과" 형식으로 적는다. 모든 AI 기능은 공통 AI 규칙(FR-030~FR-038)을 따른다.

### 5.1 공통 기반·보안 (P0)

**FR-001 첫 실행 설정**
- AC1: 사용자가 0명인 DB로 서버를 시작해 아무 주소나 접속하면 `/setup`으로 이동한다. 병원 이름, 관리자 이름, 아이디, 비밀번호(8자 이상, 확인 일치)를 입력하면 admin 계정이 생기고 로그인 상태로 대시보드에 들어간다.
- AC2: 관리자가 한 명이라도 있으면 `/setup` 접근과 설정 API 호출이 거부되고(화면은 로그인으로 이동, API는 409 `SETUP_DONE` — backend.md §2, 2026-11-02 설계 계약에 맞춰 표기 정정), 계정이 추가로 생기지 않는다.
- AC3: 코드와 설정 파일 어디에도 기본 계정이나 기본 비밀번호가 없다(코드 검색으로 확인).
- AC4: 설정 화면에서 "데모 데이터 넣기"를 선택할 수 있고, 선택하면 가상 치과 데이터가 채워진다(FR-007).

**FR-002 로그인·세션**
- AC1: 맞는 아이디·비밀번호로 로그인하면 대시보드로 가고, 틀리면 "아이디 또는 비밀번호가 맞지 않습니다"만 표시한다(어느 쪽이 틀렸는지 밝히지 않음).
- AC2: 같은 아이디로 5회 연속 실패하면 15분 동안 로그인이 거부되고 남은 시간이 안내된다. 감사 로그에 잠금이 기록된다.
- AC3: 8시간 동안 요청이 없으면 세션이 만료되어 다음 요청 때 로그인 화면으로 이동한다(시간을 조작하는 테스트로 확인).
- AC4: 로그아웃하면 그 세션 쿠키로 하는 요청이 401이 된다.
- AC5: 비밀번호는 단방향 해시로만 저장된다(DB에 평문이 없음을 테스트로 확인).
- AC6: 본인 비밀번호 변경은 현재 비밀번호가 맞을 때만 된다.

**FR-003 역할 권한**
- AC1: 2절의 권한 표에서 ❌ 칸마다 해당 역할로 화면에 접근하면 메뉴가 보이지 않는다. API를 직접 호출하면 403이 된다(역할 × 대표 API 자동 테스트).
- AC2: 비활성화된 사용자는 로그인할 수 없고, 남아 있던 세션도 무효가 된다.
- AC3: 마지막 admin은 비활성화하거나 역할을 강등할 수 없다.

**FR-004 사용자 관리**
- AC1: admin이 직원을 추가할 때 이름, 아이디, 역할, 직무(치과위생사·간호조무사·데스크·기타), 입사일만 입력한다. 그 밖의 직원 개인정보 입력란은 없다.
- AC2: admin이 임시 비밀번호로 초기화하면, 그 직원은 다음 로그인 때 비밀번호 변경 화면으로 강제로 이동한다.
- AC3: 직원 추가·변경·비활성화·초기화는 감사 로그에 남는다.

**FR-005 감사 로그**
- AC1: 로그인 성공·실패·잠금, 생성·수정·삭제, 승인, 설정 변경, 백업·복원, AI 호출(내용 원문 제외, 기능명·토큰·비용·차단 여부만)이 시각, 사용자, 행동, 대상과 함께 기록된다.
- AC2: admin은 기간·사용자·행동으로 걸러 보고 CSV로 내보낼 수 있다. 다른 역할은 접근할 수 없다.
- AC3: 화면이나 API에는 감사 로그를 수정·삭제하는 기능이 없다.

**FR-006 백업·복원**
- AC1: 서버가 켜져 있으면 하루 한 번 자동 백업이 `backups/` 폴더에 날짜가 붙은 파일로 생긴다. 서버가 그 시각에 꺼져 있었다면 다음 시작 때 바로 한 번 만든다.
- AC2: 백업이 30개를 넘으면 오래된 것부터 지워진다(보관 개수는 admin이 바꿀 수 있음).
- AC3: admin이 "지금 백업"을 누르면 즉시 백업이 생기고, 목록에서 파일을 내려받을 수 있다.
- AC4: admin이 백업을 골라 복원하면 확인 문구를 입력한 뒤 복원된다. 복원 직전 상태도 자동으로 따로 백업된다. 복원 뒤에는 그 시점 데이터가 보인다(데이터 바꾸기 → 복원 → 원래 값 확인 테스트).
- AC5: 업로드한 파일(문서·사진)도 백업에 함께 들어간다.

**FR-007 데모 데이터와 초기화**
- AC1: 데모 데이터는 가상 치과 "하늘숲치과" 기준이며 모든 모듈에 예시가 있다. 실존 인물·병원과 환자 정보는 없다.
- AC2: admin이 "데모 데이터 지우기(초기화)"를 실행하면 확인 문구 입력 뒤 업무 데이터가 모두 지워진다. 관리자 계정, 병원 설정, AI 설정, 감사 로그는 남는다. 실행 직전에 자동 백업이 생긴다.

**FR-008 대시보드 (첫 화면)**
- AC1: 로그인하면 대시보드에 오늘 날짜·근무 인원·휴가자, 오늘 할 일(체크리스트 진행률, 인수인계, 내가 처리할 승인), 재고 경고(부족·유효기간 임박), 다가오는 점검·법정 일정(D-day), 고정·최근 공지(읽음 수), AI 사용량(예산 대비)이 보인다.
- AC2: 각 영역은 데이터가 없을 때 안내 문구와 바로가기를 보여 주고, 불러오는 중이거나 오류가 났을 때도 그 상태를 표시한다.
- AC3: 각 항목을 누르면 해당 모듈의 그 항목으로 이동한다.
- AC4: 역할에 따라 보이지 않아야 할 영역(예: staff의 승인 대기)은 표시되지 않는다.

**FR-009 원내 네트워크 제한**
- AC1: 기본 설정에서 사설망(10.x, 172.16~31.x, 192.168.x)과 루프백이 아닌 주소에서 온 요청은 거부된다(설정으로 바꿀 수 있고, 위험은 README에 적는다).

### 5.2 AI 공통 (P0)

**FR-030 공급자와 데모 모드**
- AC1: API 키가 없으면 모든 AI 기능이 기능별 예시 응답(데모 모드)을 돌려주고, 화면에 "데모 모드" 표시가 보인다.
- AC2: admin이 Anthropic, OpenAI, Google Gemini 중 하나를 고르고 키를 저장하면 그 공급자로 호출한다. 공급자마다 요청 형식이 맞는지는 가짜 HTTP 서버를 쓴 자동 테스트로 확인한다.
- AC3: "연결 확인" 버튼은 아주 작은 요청으로 키가 유효한지 확인하고 결과를 쉬운 말로 알려 준다.

**FR-031 키 보안**
- AC1: 저장된 API 키는 브라우저로 내려가지 않는다. 설정 화면에는 끝 4자리만 가려서 보이고, API 응답·HTML·로그 어디에도 키 원문이 없다(자동 검사).
- AC2: 키는 서버에 암호화해서 저장한다. 암호화 키는 DB와 다른 파일에 둔다.

**FR-032 개인정보 필터**
- AC1: AI로 보낼 모든 텍스트를 서버에서 먼저 검사한다. 주민등록·외국인등록번호, 휴대·일반 전화번호, 이메일, 카드번호, 계좌번호, 여권번호를 감지한다.
- AC2: 감지 결과는 관리자 설정에 따라 처리한다. 기본은 **가리고 보내기**이고, 원문은 `[전화번호]` 같은 표시로 바뀌어 전송된다. 사용자에게는 "전화번호 1건을 가리고 보냈습니다"가 표시된다. 주민등록번호와 카드번호는 기본이 **차단**이며, 이유를 안내하고 보내지 않는다.
- AC3: 병원 대표번호처럼 관리자가 등록한 허용 목록은 가리지 않는다.
- AC4: AI 응답 텍스트와 사진 인식 결과도 같은 검사를 거쳐 저장·표시 전에 가린다.
- AC5: 모든 AI 입력창 바로 위에 "환자 개인정보 입력 금지" 안내가 보인다.
- AC6: 패턴별 감지·미감지 예시 50개 이상을 자동 테스트하고, 날짜·금액·품목코드처럼 잘못 감지하기 쉬운 경우도 포함한다.

**FR-033 기능별 모델 등급**
- AC1: 기능마다 등급(빠름·표준·고급)이 정해져 있고 admin이 바꿀 수 있다. 등급마다 공급자별 모델이 연결되어 있다.
- AC2: 사용자가 등급을 고를 수 있는 기능(문서 작성기 등)에서는 등급별 예상 비용이 표시된다.
- AC3: admin은 기능별·역할별로 AI 사용을 끌 수 있고, 꺼진 기능은 화면에서 비활성 안내가 나오며 API에서도 거부된다.

**FR-034 사용량·비용 기록**
- AC1: 호출마다 시각, 사용자, 기능, 공급자, 모델, 입력·출력 토큰, 예상 비용(원·달러), 성공 여부, 개인정보 처리 결과가 기록된다. 프롬프트 원문은 저장하지 않는 것이 기본이다.
- AC2: 데모 모드 호출은 비용 0원과 "데모"로 기록된다.
- AC3: 관리 화면의 사용량 대시보드에서 이번 달 비용, 예산 대비 비율, 기능별·사용자별·일별 사용량을 본다.

**FR-035 월 예산**
- AC1: admin이 월 예산(원)을 정한다. 이번 달 누적이 80%를 넘으면 admin에게 알림이 가고 대시보드에 경고가 보인다.
- AC2: 100%에 닿으면 새 AI 요청이 차단되고 "이번 달 AI 예산을 모두 사용했습니다. 관리자에게 한도 조정을 요청하세요"가 표시된다.
- AC3: admin이 한도를 올리면 즉시 다시 사용할 수 있다. 매월 1일에 누적이 새로 시작된다.

**FR-036 모델·가격 표 편집**
- AC1: 작업 시점에 공식 문서로 확인한 모델명과 백만 토큰당 입력·출력 단가가 확인 날짜, 출처 URL과 함께 기본값으로 들어 있다.
- AC2: admin이 모델명, 단가, 환율을 고치면 그 뒤 호출부터 새 값으로 비용을 계산한다.

**FR-037 오류 안내**
- AC1: 시간 초과, 키 오류, 한도 초과(공급자 측), 네트워크 끊김, 공급자 장애가 나면 각각 다른 쉬운 한국어 안내와 다음 행동(다시 시도, 관리자에게 키 확인 요청 등)이 표시된다. 기술 오류 원문은 화면에 노출하지 않는다.
- AC2: 시간 초과 기준은 기능별로 정해져 있고(긴 문서는 더 길게) 넘으면 요청을 끊는다.

**FR-038 법률 고지**
- AC1: AI 결과 화면과 의료광고 점검 결과에 "AI 초안은 참고용이며 법률 자문을 대신하지 않습니다"가 표시된다. 설정 화면에는 서비스 이용 고지문이 있다.

### 5.3 A. 데스크·소통 (P0, 핵심)

**FR-040 공지·인수인계 보드**
- AC1: manager 이상은 공지를 쓰고 고정할 수 있고, 모든 역할은 인수인계를 쓸 수 있다. 각 글에는 분류, 작성자, 시각이 붙는다.
- AC2: 글을 열면 읽음으로 표시되고, 작성자와 manager 이상은 읽은 사람과 안 읽은 사람 목록을 본다.
- AC3: 새 공지가 올라오면 알림센터에 알림이 생긴다(FR-090이 완성된 뒤 연결).
- AC4: 인수인계에는 "처리 완료" 표시가 있고, 완료되지 않은 것이 대시보드에 보인다.

**FR-041 오픈·마감 체크리스트**
- AC1: manager 이상이 오픈·마감 체크리스트 항목을 편집한다(추가, 순서 변경, 담당 역할 지정).
- AC2: 오늘 날짜의 체크 상태는 누가 언제 체크했는지와 함께 저장되고, 날짜가 바뀌면 새로 시작한다. 지난 날짜의 기록은 조회만 된다.
- AC3: 대시보드에 오늘 진행률이 보이고, 체크하면 바로 반영된다.

**FR-042 전화 응대·안내 스크립트 생성 (AI)**
- AC1: 병원 기본 정보(진료시간, 점심시간, 휴진일, 주차, 위치·교통, 보험 일반 안내 문구)를 설정에 한 번 저장해 두면 스크립트 생성 때 자동으로 반영된다.
- AC2: 상황(예약 변경 안내, 주차 문의, 진료시간 문의, 보험 일반 문의 등)과 말투를 고르면 AI가 응대 스크립트를 만든다. 결과는 복사하거나 스크립트 보관함에 저장한다.
- AC3: 저장한 스크립트는 검색하고 분류할 수 있다.

**FR-043 온라인 리뷰 답글 초안 (AI)**
- AC1: 리뷰 내용을 붙여 넣으면 개인정보 필터를 거친 뒤 답글 초안 2~3개(말투별)를 받는다.
- AC2: 답글 초안은 의료광고 점검(FR-120)을 자동으로 거친다. 그 기능을 켜지 않았다면 점검 안내만 표시한다. 답글에 진료 사실을 확인해 주는 표현이 들어가면 경고한다.

**FR-044 안내 문자·안내문 템플릿**
- AC1: 문자·안내문 템플릿을 만들고 분류·검색하며 `{진료시간}` 같은 병원 정보 치환자를 쓸 수 있다. 환자 이름 치환자는 제공하지 않는다.
- AC2: AI로 템플릿 초안을 만들 수 있고, 글자 수(단문 90바이트·장문 기준)가 표시된다.
- AC3: 실제 발송 기능은 없고, 복사만 된다.

### 5.4 B. 재고·구매 (P0, 핵심)

**FR-050 품목 관리**
- AC1: manager 이상은 품목을 등록한다(이름, 분류, 단위, 적정 재고, 유효기간 관리 여부, 기본 거래처, 보관 위치, 메모). 같은 이름이 있으면 경고한다.
- AC2: 목록에서 검색하고, 분류·상태(부족·유효기간 임박·정상)로 거르고 정렬한다. 현재고와 적정 대비가 막대로 보인다.
- AC3: 입출고 기록이 있는 품목은 삭제 대신 "사용 안 함"으로 바뀐다.

**FR-051 입출고 기록**
- AC1: 모든 역할이 출고를 기록한다. 품목 검색 → 수량 입력 → 저장의 2단계이며, 저장하면 현재고가 줄어든다.
- AC2: 입고에는 수량, 단가, 거래처, 유효기간(관리 품목), 로트를 기록한다. 입고하면 현재고가 늘어난다.
- AC3: 현재고는 입출고 기록 합으로 계산해서 기록과 항상 일치한다. 재고 조정(실사)도 사유와 함께 기록한다.
- AC4: 현재고보다 많이 출고하면 경고하고 확인을 받는다. 수량 0 이하는 거부한다.

**FR-052 적정 재고·유효기간 알림**
- AC1: 현재고가 적정 재고 아래면 "부족", 적정의 120% 이하이면 "곧 부족"으로 표시된다.
- AC2: 유효기간이 관리자가 정한 일수(기본 30일) 안이면 "임박(D-n)", 지났으면 "만료"로 표시된다. 유효기간은 입고 로트별로 판단한다.
- AC3: 상태가 바뀌면 대시보드 재고 경고와 알림센터에 반영된다.

**FR-053 거래처 관리**
- AC1: manager 이상은 거래처(상호, 담당자 이름, 업무용 연락처, 이메일, 주문 방법, 메모)를 관리한다. 거래처는 사업자 정보라서 개인정보 원칙의 대상이 아니다. AI로 보낼 때는 거래처 연락처를 넣지 않는다.

**FR-054 발주서 자동 작성**
- AC1: "발주서 만들기"를 누르면 부족·곧 부족 품목이 기본 거래처별로 묶이고, 권장 수량(적정 × 1.5 − 현재고, 단위 올림)이 미리 채워진 초안이 만들어진다.
- AC2: 수량·품목을 고친 뒤 확정하면 발주 번호가 붙은 발주서가 저장된다. 인쇄용 화면(A4)에는 병원 정보, 거래처, 품목, 수량, 최근 단가, 합계가 들어간다. 브라우저 인쇄와 PDF 저장으로 출력된다.
- AC3: 발주서 상태는 작성 → 발주함 → 입고 완료로 바뀌고, "입고 처리"를 누르면 발주 품목이 입고 기록 초안으로 넘어간다.

**FR-055 단가 변동 기록**
- AC1: 입고할 때마다 품목·거래처별 단가가 기록되고, 품목 상세에서 단가 추이(표와 작은 그래프)를 본다.
- AC2: 직전 단가보다 일정 비율(기본 5%) 넘게 오르면 목록과 입고 화면에 ▲ 표시가 나온다.

**FR-056 CSV 가져오기·내보내기**
- AC1: 품목·거래처·입출고 기록을 CSV(엑셀 호환, UTF-8 BOM)로 내보낸다. 엑셀에서 열어도 한글이 깨지지 않는다.
- AC2: 품목 CSV 가져오기는 양식 내려받기 → 업로드 → 미리보기(새 항목·변경·오류 줄 표시) → 확정 순서다. 오류가 있는 줄은 이유와 함께 표시되고 건너뛸 수 있다. EUC-KR(CP949)로 저장된 엑셀 CSV도 읽는다.

### 5.5 C. 행정·서류 (P0, 핵심)

**FR-060 AI 문서 작성기**
- AC1: 문서 종류(환자 일반 안내문, 공문, 내부 규정, 업무 매뉴얼, 리뷰 답글, 기타)와 요점, 분량, 말투, 등급을 고르면 초안이 생긴다. 공문은 수신·참조·제목·본문·붙임 형식을 따른다.
- AC2: 초안은 화면에서 바로 고칠 수 있다(제목, 문단, 목록, 굵게). "다시 쓰기"와 "더 짧게·더 공손하게" 같은 부분 수정을 요청할 수 있다.
- AC3: 문서를 서식 보관함에 저장하면 버전이 남는다.
- AC4: 응답은 생성되는 대로 화면에 이어서 표시되고, 중간에 멈출 수 있다.

**FR-061 회의록 요약 (AI)**
- AC1: 회의 메모를 붙여 넣으면 결정 사항, 할 일(담당 역할·기한), 논의 요약으로 정리된다. 할 일은 클릭 한 번에 인수인계·공지로 보낼 수 있다.

**FR-062 서식 보관함**
- AC1: 서식(문서·양식)을 폴더와 태그로 분류해 저장하고 검색한다. 파일 업로드(pdf, docx, xlsx, hwp는 보관만, 이미지)와 서비스 안에서 작성한 문서를 함께 관리한다.
- AC2: 업로드 파일 크기 제한(기본 20MB)과 허용 확장자를 검사하고, 거부 이유를 안내한다.

**FR-063 인쇄 출력**
- AC1: 문서·발주서·체크리스트·근무표·점검 기록에 인쇄 전용 화면이 있다. A4 여백, 머리말(병원명), 쪽 번호가 들어가고 메뉴·버튼은 인쇄되지 않는다.

### 5.6 G. 원내 AI 도우미 (P0, 핵심)

**FR-070 원내 문서 올리기**
- AC1: manager 이상이 원내 매뉴얼·규정을 올린다(txt, md, pdf, docx, 또는 서비스 안 문서 선택). 텍스트가 추출되어 검색 가능한 조각으로 나뉘고, 처리 상태(처리 중·완료·실패와 이유)가 표시된다.
- AC2: 문서를 지우면 검색 대상에서도 빠진다. 문서마다 공개 범위(전체·manager 이상)를 정할 수 있다.
- AC3: 올릴 때 개인정보 패턴을 검사해서 감지된 부분을 알리고, 가린 뒤 저장할지 고르게 한다.

**FR-071 질문과 근거**
- AC1: 사용자가 질문하면 권한 범위 안의 문서에서 관련 조각을 찾아, 그 내용만 근거로 답한다. 답 아래에 근거 문서 이름, 해당 부분 발췌, 문서로 바로 가는 링크가 표시된다.
- AC2: 관련 문서가 없으면 지어내지 않고 "원내 문서에서 찾지 못했습니다"라고 답하고 어떤 문서를 올리면 되는지 안내한다.
- AC3: 데모 모드에서도 문서 검색과 근거 표시는 실제로 동작하고, 답 문장만 예시 형식으로 만든다.
- AC4: 대화는 사용자별로 최근 기록이 남고, 사용자가 지울 수 있다.

### 5.7 D. 인사·근무

**FR-080 연차·휴가 신청과 승인 (P0)**
- AC1: 직원이 날짜, 종류(연차·반차 오전/오후·병가·기타), 사유(선택)로 신청하면 manager 이상에게 알림이 가고 대시보드 승인 대기에 보인다.
- AC2: 승인·반려(반려 사유 필수)하면 신청자에게 알림이 가고, 승인된 휴가는 근무표에 반영된다.
- AC3: 직원별 올해 사용 일수와 admin이 정한 부여 일수 대비 잔여가 보인다. 법정 연차 자동 계산은 하지 않는다(미결 아님, 제외).
- AC4: 같은 날 휴가자가 정해진 수를 넘으면 승인 화면에 경고가 나온다.

**FR-081 근무표 (P1)**
- AC1: 주간·월간 달력에서 직원 × 날짜 칸에 근무 유형(종일·오전·오후·야간·휴무 등, 관리자가 정의, 시간 포함)을 넣는다. 칸 클릭 → 유형 선택의 1~2번 클릭으로 끝난다.
- AC2: 지난주 패턴 복사, 승인된 휴가 자동 표시, 날짜별 근무 인원 합계가 있다.
- AC3: 근무표를 인쇄할 수 있고, 모든 역할이 조회한다(편집은 manager 이상).

**FR-082 교육 이수 기록 (P1)**
- AC1: 교육 항목(감염관리, 개인정보, 방사선 안전 등)과 주기를 정하고, 직원별 이수일과 증빙 파일을 기록한다. 다음 이수 예정일이 계산되어 임박하면 알림이 간다.

**FR-083 신규 직원 온보딩 (P1)**
- AC1: 온보딩 체크리스트 템플릿(직무별)을 만들고 신규 직원에게 배정하면, 직원과 담당자가 진행률을 함께 본다.
- AC2: AI가 직무에 맞는 온보딩 체크리스트 초안을 만들 수 있다.

**FR-084 채용 공고·면접 질문 초안 (AI, P1)**
- AC1: 직무, 근무 조건(병원이 입력), 우대 사항을 넣으면 채용 공고 초안과 면접 질문 목록(직무·태도·상황 질문)이 나온다. 차별 소지 표현(나이·성별·결혼 여부 등)이 있으면 경고한다.

### 5.8 E. 시설·법정 관리

**FR-100 법정 의무 일정 (P0)**
- AC1: 기본 일정 템플릿으로 방사선 장비 정기검사, 방사선 안전관리책임자·관계종사자 교육, 종사자 선량 측정, 감염관리 교육, 소방 점검·훈련, 개인정보 보호 교육, 의료폐기물 배출자 교육·보관 등이 들어 있다. 각 항목에는 주기, 근거 설명, 출처, 확인 상태(확인됨 / 권장값(법정 주기 없음) / 확인 필요), 적용 조건(항상 / 해당 시, "해당 없음"으로 끌 수 있음)이 있다. 기본값은 TRD TD-022를 따른다.
- AC2: 공식 출처로 주기를 확인하지 못한 항목은 "확인 필요" 표시가 붙고, admin이 주기와 상태를 고칠 수 있다.
- AC3: 마지막 수행일을 기록하면 다음 예정일이 계산된다. 예정일이 지정 일수(기본 30일) 안이면 대시보드와 알림에 D-day로 보이고, 지나면 "기한 지남"으로 표시된다.
- AC4: 화면에 "법정 주기는 법령 개정으로 바뀔 수 있으니 관할 기관 안내를 확인하세요"라는 고지가 있다.

**FR-101 장비 점검·유지보수 이력 (P1)**
- AC1: 장비(이름, 종류, 설치일, 업체, 점검 주기)를 등록하고 점검·수리 이력(일자, 내용, 비용, 업체, 첨부)을 기록한다. 다음 점검일이 계산된다.

**FR-102 멸균기 점검 기록 (P1)**
- AC1: 멸균기별로 일일·주간 기록(B&D 테스트, BI·CI 결과, 사이클 번호, 온도·압력·시간, 담당자, 판정)을 남긴다. 입력 양식에 환자 관련 입력란은 없다.
- AC2: "불합격"으로 기록하면 manager 이상에게 즉시 알림이 가고, 조치 내용을 기록하기 전까지 대시보드에 남는다.
- AC3: 기간별 기록을 인쇄·CSV로 내보낸다.

### 5.9 F. 운영 지표 (P1)

**FR-110 지출 기록과 분류**

- AC2: 재고 입고를 기록할 때 지출로도 함께 기록할지 고를 수 있다.
- AC3: 환자와 연결되는 매출 입력란은 없다.

**FR-111 월별 요약 대시보드**

- AC2: AI "이번 달 요약" 버튼을 누르면 집계 숫자만 보내 변동 원인 후보와 절약 제안 문장을 받는다.

### 5.10 추가 기능 (IDEA에서 선택, P1)

**FR-090 원내 알림센터**
- AC1: 상단 종 아이콘에 읽지 않은 알림 수가 보인다. 목록에서 누르면 해당 항목으로 이동하고 읽음 처리된다.
- AC2: 알림 종류는 연차 신청·결과, 재고 부족·유효기간, 점검·법정 일정 임박, 새 공지, 멸균 불합격, AI 예산 경고다. 알림은 역할·담당에 맞는 사람에게만 간다.
- AC3: 새 알림은 화면을 새로 고치지 않아도 1분 안에 나타난다.

**FR-091 휴대폰 홈 화면 추가 (PWA)**
- AC1: 휴대폰 브라우저에서 "홈 화면에 추가"를 하면 앱 아이콘과 이름으로 열린다. 화면이 휴대폰 너비(390px)에서 가로 스크롤 없이 쓸 수 있다.
- AC2: 앱이 열려 있는 동안 서버 연결이 끊기면 "원내 와이파이에 연결되어 있는지 확인하세요" 안내 띠가 나오고, 다시 연결되면 사라진다. 원내 접속은 http(인증서 없음)라서 처음부터 연결되지 않을 때는 브라우저 기본 오류 화면이 나오며, 이 화면은 바꿀 수 없다. (2026-11-02 사용자 선택: "http 유지", TRD TD-017)

**FR-120 의료광고 문구 점검 (AI)**
- AC1: 글을 붙여 넣거나 다른 기능의 결과에서 "광고 문구 점검"을 누르면 규칙 기반 1차 점검과 AI 2차 점검을 거친다. 1차 점검은 금지·주의 표현 사전을 쓴다: 최고·유일·100%, 치료 전후 비교, 치료 경험담, 과도한 할인·무료 강조, 비교 광고 등. 결과로 위험 표현, 이유, 대체 표현 제안이 표시된다.
- AC2: 결과에 "법률 자문이 아니며, 의료광고 사전심의 대상 여부는 관련 기관에 확인하세요" 고지가 붙는다.
- AC3: 규칙 사전은 admin이 추가·수정할 수 있다.

**FR-121 블로그·SNS 홍보 글 초안 (AI)**
- AC1: 주제(예: 스케일링 주기 안내, 칫솔질 방법), 채널(블로그·인스타그램), 분량을 고르면 초안이 나오고 의료광고 점검이 자동으로 실행된다.

**FR-122 명세서·영수증 사진 → 입고·지출 입력 (AI)**
- AC1: 업로드 화면에 "환자 정보·카드번호가 보이면 가리고 올리세요" 경고가 있고, 확인 체크를 해야 전송 버튼이 켜진다.
- AC2: AI가 거래처, 일자, 품목, 수량, 단가, 합계를 읽어 표 형태의 초안을 만든다. 품목은 기존 품목과 이름이 비슷한 것으로 자동 연결 후보가 제시된다. 사용자가 확인·수정한 뒤 저장해야 입고(그리고 선택 시 지출)로 기록된다.
- AC3: 읽은 글자에서 개인정보 패턴이 감지되면 가린 뒤 표시하고 안내한다.
- AC4: 이미지는 전송 전에 크기를 줄인다(긴 변 기준 최대 1600px). 줄이는 일은 브라우저가 업로드 전에 하고, 서버는 크기·용량 상한을 다시 검사한다(TD-012). 데모 모드에서는 예시 명세서 결과가 나온다.
- AC5: 사진 기능은 이미지 입력을 지원하는 모델이 설정되어 있을 때만 켜진다.

## 6. 비기능 요구 (NFR)

NFR-003·NFR-005의 수치는 2026-11-02에 사용자가 "이대로 확정"했다(OQ-004 해소).

- **NFR-001 개인정보 구조**
  - AC1: DB에 환자 관련 테이블과 열(환자명, 주민번호, 차트번호, 진단, 진료 내용 등)이 없다. 자동 테스트가 스키마의 열 이름을 금지어 목록과 대조해서 확인한다.
  - AC2: 직원 정보는 FR-004의 항목만 저장된다.
- **NFR-002 보안**
  - AC1: CSRF 토큰 없이 상태를 바꾸는 요청을 보내면 거부된다.
  - AC2: 사용자 입력(공지, 문서 등)에 스크립트를 넣어도 실행되지 않는다(XSS 테스트).
  - AC3: 모든 SQL은 매개변수 바인딩을 쓴다. 인젝션 문자열 테스트를 통과한다.
  - AC4: 보안 헤더(CSP, X-Content-Type-Options, frame-ancestors, Referrer-Policy)가 응답에 있다.
  - AC5: 모든 API 입력은 스키마로 검증되고, 잘못된 입력에는 400과 한국어 안내가 돌아온다.
  - AC6: `npm audit`에 high/critical 취약점이 0건이다.
  - AC7: docs/SECURITY.md 체크리스트의 모든 항목에 점검 결과가 적혀 있다.
- **NFR-003 설치·실행 (Windows)**
  - AC1: Node.js만 설치된 깨끗한 Windows에서 README 절차대로 30분 안에 설치를 끝낸다. 첫 `start.bat` 실행 때 필요한 준비가 자동으로 끝난다.
  - AC2: 이후에는 `start.bat` 더블클릭으로 서버가 켜지고 브라우저가 열린다. 창에 접속 주소(이 PC와 원내 다른 기기용 IP)가 한국어로 표시된다. `stop.bat` 또는 창 닫기로 끈다.
  - AC3: 처음 설치한 뒤에는 인터넷이 없어도 실행과 모든 화면이 동작한다(폰트·아이콘 포함, 실제 AI 호출만 제외).
  - AC4: 포트가 이미 쓰이고 있거나 Node.js가 없을 때 원인과 해결법이 한국어로 표시된다.
- **NFR-004 데이터 저장**
  - AC1: 업무 데이터는 단일 DB 파일 하나와 업로드 폴더에 저장된다. 서버를 끈 상태에서 `data` 폴더를 복사하면 그대로 백업이 된다.
- **NFR-005 성능** `(사용자 확정)`
  - AC1: 데모 데이터의 10배 규모(품목 1,000개, 입출고 2만 건)에서 서버 PC 기준 주요 목록 API의 p95가 300ms 이하다.
  - AC2: 20명 동시 접속 시나리오를 부하 스크립트로 돌렸을 때 오류가 0건이다.
  - AC3: 첫 화면은 원내 네트워크에서 2초 안에 표시된다.
- **NFR-006 화면 품질·반응형**
  - AC1: 데스크톱 1440px, 태블릿 1024px·768px, 휴대폰 390px에서 가로 스크롤이 생기지 않고, 겹침·잘림이 없다(스크린샷을 직접 보고 확인).
  - AC2: 라이트·다크 모드를 지원하고, 시스템 설정을 따르거나 직접 고를 수 있다.
  - AC3: 모든 목록 화면에 빈 상태, 불러오는 중, 오류 상태가 있다.
  - AC4: 확정된 디자인 기준(`docs/DESIGN.md`)의 토큰, 컴포넌트, 시각 기준을 따른다.
- **NFR-007 접근성**
  - AC1: 마우스 없이 키보드만으로 로그인, 출고 기록, 문서 생성, 연차 신청을 끝낼 수 있다. 포커스가 눈에 보인다.
  - AC2: 본문 텍스트 대비가 4.5:1 이상이다(자동 검사 도구 기준 위반 0건, 두 테마 모두).
  - AC3: 폼에 레이블이 있고, 오류가 입력란과 연결되어 읽힌다.
- **NFR-008 키 없는 검증**
  - AC1: API 키가 없는 상태에서 설치, 실행, 전체 자동 테스트, E2E가 모두 통과한다. 실제 공급자 호출은 테스트에서 하지 않는다.
- **NFR-009 사용성**
  - AC1: 자주 하는 작업(출고 기록, 체크, 연차 신청, 공지 확인)은 대시보드에서 3번 클릭 안에 끝난다.
  - AC2: 화면에 보이는 모든 문구와 오류는 한국어이고, 기술 용어 대신 업무 용어를 쓴다.
- **NFR-010 코드 주석**
  - AC1: 모든 소스 파일 맨 위에 "이 파일이 하는 일" 한국어 요약이 있다(자동 검사).
  - AC2: 주요 함수에는 쉬운 한국어 설명이 있다.
- **NFR-011 문서 산출물**
  - AC1: README.md(원문 12절 항목 전부, 스크린샷 포함), docs/LLM_GUIDE.md, docs/COST.md(원문 13절 항목 전부), docs/PLAN.md, docs/DECISIONS.md, docs/SECURITY.md, PROGRESS.md가 있다. 각 문서에 원문이 요구한 소제목이 빠짐없이 있다.
- **NFR-012 테스트 정직성**
  - AC1: 완료 판정은 자동 테스트, 실제 서버 실행, E2E, 스크린샷 확인 결과로만 한다. 확인하지 않은 항목은 "미검증"으로 보고한다. 테스트를 통과시키려고 기준을 약하게 바꾸지 않는다.

## 7. 가정·제약

- 서버 PC는 Windows 10/11 64비트이고 Node.js LTS를 설치할 수 있다. 확인 결과 개발 PC에는 Node 24가 있다. `(에이전트 기본값)`
- 원내 네트워크는 공유기 하나 아래의 사설망이다. 고정 IP 설정은 README에서 권장 사항으로 안내한다. `(에이전트 기본값)`
- 실제 LLM 호출은 사용자가 키를 넣은 뒤에만 일어난다. 실제 공급자 응답 품질, 사진 인식 정확도는 이번 Loop에서 검증할 수 없다(OQ-006).
- 기술 스택, 문서 검색 방식, PDF 출력 방식은 TRD에서 정한다. 사용자 원문 9절 기준을 따르고, 결정은 위임받았다.
