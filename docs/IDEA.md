# IDEA — 치과 원내 업무 AX 웹 서비스

> 현재 단계: 아이디어 구체화 완료 → **PRD v1.0 확정 (2026-11-02, `docs/PRD.md`, 디자인 `docs/DESIGN.md`)** → 다음: `trd-generator`
> 원문: 사용자가 붙여넣은 상세 요구서(0~14절). 아래는 원문에서 확정된 것 + 대화로 고른 것 + 에이전트 가정의 구분 정리다.
> 원문의 "외부 플러그인 사용 금지·묻지 않기" 조항은 사용자 본인 지시("harness_loop_fullstack_kor 플러그인으로 idea부터 진행")가 우선한다. 플러그인 흐름에 따라 단계마다 보고하고 확인받는다.

## 1. 문제·사용자·가치

- **문제**: 치과 병의원의 진료 외 업무(데스크 소통, 재고·발주, 서류, 근무, 시설·법정 점검, 지출)가 엑셀·한글 파일, 카카오톡 단톡방, 별도 프로그램에 흩어져 있다. 반복되는 문서 작성과 기록에 시간이 많이 든다. (사용자 응답으로 현재 방식 확인)
- **첫 사용자**: 직원 5~20명 규모 치과의 원장, 실장(데스크), 치과위생사, 간호조무사. 사용자 본인은 코딩을 모르는 치과의사다.
- **현재 대안 대비 가치**
  - 흩어진 기록을 원내 웹 서비스 하나로 모은다. 같은 네트워크의 PC·태블릿·휴대폰에서 접속한다.
  - 단톡방에 묻히던 공지·인수인계·연차 요청은 보드와 알림센터로 옮겨 확인 여부가 남게 한다.
  - 엑셀 재고표 대신 적정 재고·유효기간 알림, 발주서 자동 작성을 쓴다.
  - 반복 문서(안내문, 공문, 스크립트, 리뷰 답글, 채용 공고)는 AI가 초안을 쓴다.
  - 환자 정보는 저장하지 않고 AI로 보내지도 않는 구조라, LLM API를 부담 없이 쓸 수 있다.

## 2. 핵심 흐름 (가치를 얻는 순간)

1. 아침에 대시보드를 연다 → 오늘 할 일, 재고 경고, 다가오는 점검, 공지를 한눈에 본다 → 오픈 체크리스트를 처리한다.
2. 재료를 출고 기록한다 → 적정 재고 아래로 내려가면 알림이 온다 → 거래처별 발주서가 자동으로 만들어진다 → 인쇄하거나 PDF로 저장한다.
3. 거래명세서 사진을 올린다 → 경고를 보고 확인 체크를 한다 → AI가 품목·수량·단가를 읽어 입고 초안을 만든다 → 사람이 확인하고 저장하면 단가 변동이 기록된다.
4. AI 문서 작성기에서 종류(공문, 안내문, 규정, 매뉴얼)를 고르고 요점을 입력한다 → 개인정보 검사를 거친다 → 초안이 나온다 → 의료광고 점검을 한다(해당 시) → 인쇄에 맞춰 출력한다.
5. 원내 매뉴얼·규정 문서를 올린다 → 원내 AI 도우미에게 묻는다 → 근거 문서와 함께 답을 받는다.
6. 직원이 연차를 신청한다 → 원장·실장이 승인한다 → 근무표와 알림센터에 반영된다.

## 3. 첫 버전 범위

**출발점**: 원문 5절의 A~H 전부.
**깊게 만들 핵심** (사용자 선택): **B 재고·구매**, **A 데스크·소통**, **C·G AI 문서 작성기와 원내 AI 도우미**. 나머지(D·E·F·H)는 실사용 가능한 수준으로 만든다.

**원문에 없던 추가 후보 중 첫 버전에 포함** (사용자 선택)
- 의료광고 문구 점검과 블로그·SNS 홍보 글 초안. 법률 자문이 아니라는 고지를 함께 단다.
- 원내 알림센터(연차 승인, 재고 부족, 점검 임박, 새 공지)와 휴대폰 홈 화면 추가(PWA)
- 채용 공고·면접 질문 초안
- 명세서·영수증 사진 → 입고·지출 자동 입력. 사진은 서버에서 개인정보 검사가 어렵기 때문에 다음 보호 방식을 쓴다(사용자 선택).
  - 업로드 화면에 "환자 정보·카드번호가 보이면 가리고 올리세요" 경고를 띄운다.
  - 확인 체크를 해야 전송된다.
  - AI가 읽어 온 글자를 다시 개인정보 검사해서 감지되면 가린다.

**나중(확장)**: 바코드·QR 스캔 출고, AI 근무표 자동 배정 제안, 회의 음성 → 회의록(음성 인식).

**제외 (개인정보 원칙·외부 계약 필요)**
- 예약·환자 관리, 보험청구, 전자차트 연동, 기공 의뢰서(환자명 포함), 급여 계산, 직원 평가
- 카카오 알림톡·문자 실제 발송. 문구 템플릿만 제공한다.
- 한글(HWP) 파일 직접 변환. 무인 변환 시 대화상자 때문에 멈춘 이력이 있다. 업로드는 txt/md/pdf/docx로 받고, 출력은 인쇄·PDF·CSV(엑셀)로 한다.

## 4. 확정된 운영 결정 (사용자 선택)

- **AI 사용 권한**: 모든 직원이 기본으로 쓰고 병원 전체 월 예산을 함께 쓴다. 관리자는 기능별·역할별로 켜고 끌 수 있다.
- **예산 초과**: 80%에서 관리자에게 경고, 100%에서 AI 요청을 차단한다. 관리자가 한도를 올리면 즉시 풀린다.
- **화면 분위기**: 차분한 청록(틸) 포인트에 밝은 회백색 바탕(다크 모드 지원). Linear·Notion·Toss 수준의 정돈감. 실제 시안은 PRD 단계에서 미리보기로 확정받는다(아이디어 합의는 디자인 최종 승인이 아님).
- **기존 자료 이전**: 엑셀·한글·단톡방·별도 프로그램을 쓰고 있으므로 CSV(엑셀) 가져오기·내보내기와 인쇄 양식 품질을 중요하게 본다.

## 5. 제약 (원문에서 확정)

- **개인정보**
  - 환자 이름·연락처·주민번호·차트번호·진료정보를 담는 테이블이나 입력란을 만들지 않는다.
  - AI로 보내는 모든 텍스트는 서버에서 먼저 개인정보 패턴을 검사해서 막거나 가리고, 사용자에게 이유를 알린다.
  - AI 입력창 근처에 "환자 개인정보 입력 금지" 안내를 둔다.
  - 직원 정보는 업무에 필요한 최소한만 저장한다.
  - 법률 자문을 대신하지 않는다는 점을 서비스 안에 고지한다.
- **운영 환경**
  - 원내 Windows PC 한 대가 서버 역할을 하고, 원내 네트워크에서만 접속한다.
  - README만 보고 30분 안에 설치할 수 있어야 하고, 매일 실행은 `start.bat` 더블클릭으로 끝난다.
  - 데이터는 단일 파일 DB에 저장해서 백업이 파일 복사로 끝나게 한다.
- **AI 연동**
  - API 호출은 서버에서만 하고, 키는 브라우저에 노출하지 않는다.
  - Anthropic·OpenAI(가능하면 Gemini)와 데모 모드를 지원한다.
  - 기능별로 모델 등급을 정하고, 호출마다 토큰과 비용을 기록한다.
  - 모델명과 가격은 작업 시점에 공식 문서로 확인하고 관리 화면에서 고칠 수 있게 한다.
  - 오류는 쉬운 한국어로 안내한다.
  - **API 키 없이도 전체 설치·실행·테스트가 가능**해야 한다.
- **보안**
  - 로그인 필수, 비밀번호 해시, 역할 3단계(원장·관리자 / 실장 / 직원)
  - 첫 실행 때 관리자 계정을 만드는 설정 화면. 기본 비밀번호는 두지 않는다.
  - 세션 만료, 로그인 시도 제한, CSRF·XSS·SQL 인젝션 방어, 보안 헤더
  - 감사 로그, 매일 자동 백업과 복원, 의존성 취약점 점검
- **디자인**
  - 한국어 폰트를 프로젝트 안에 포함해서 인터넷 없이도 보이게 한다.
  - 데스크톱·태블릿 반응형, 라이트·다크 모드, 기본 접근성
  - 빈 화면·로딩·오류 상태까지 다듬는다.
  - 가상 치과 데모 데이터를 넣고, 지울 수 있는 "초기화" 기능을 둔다.
- **코드·문서**
  - 모든 파일 맨 위와 주요 함수에 쉬운 한국어 주석을 단다.
  - 원문 12~13절의 문서: README, docs/LLM_GUIDE.md, COST.md, PLAN.md, DECISIONS.md, SECURITY.md, PROGRESS.md
  - 원문의 PLAN·PROGRESS·DECISIONS는 플러그인 산출물(PRD/TRD/Architecture/plan_setup)과 연결해서 만든다. 원문이 요구한 파일명은 유지한다.
- **환경 (조사 결과)**
  - 작업 폴더는 비어 있다(새 프로젝트, git 저장소 아님).
  - Node.js v24.13.0, npm 11.6.2, Python 3.12.9, Git 2.54가 설치되어 있다.

## 6. 관찰 가능한 성공 기준

- 새 DB 상태에서 README 절차대로 설치하고 `start.bat`을 실행하면 첫 관리자 설정 화면이 뜬다. 같은 네트워크의 다른 기기에서도 접속된다.
- API 키가 없을 때 모든 AI 기능이 데모 응답으로 동작한다. 키를 넣으면 실제 공급자로 동작하고, 토큰·비용이 기록된다.
- 개인정보 패턴(주민번호, 전화번호, 이메일, 카드·계좌번호)이 들어간 입력은 AI로 보내기 전에 막히거나 가려지고, 이유가 표시된다.
- 핵심 흐름 1~6을 브라우저 E2E 테스트로 통과한다. 자동 테스트도 전부 통과한다. 테스트를 약하게 고쳐서 통과시키지 않는다.
- 주요 화면 스크린샷(라이트·다크, 데스크톱·태블릿)을 직접 보고 깨짐이 없음을 확인한다.
- 예산 80% 경고와 100% 차단이 실제로 동작한다.
- 매일 백업이 생성되고, 복원 후 데이터가 돌아온다.
- 보안 체크리스트(docs/SECURITY.md)를 직접 점검했고, npm audit에 고위험 취약점이 없다.

## 7. 자율운영 합의 (PRD `## 자율운영 합의`로 연결)

- **목표**: MVP를 완성하고, 확장('나중' 후보 포함)까지 가능한 데 까지 진행한다(사용자 지시: "MVP 넘어 확장까지 전부").
- **시간 상한**: Loop 실행 시작부터 **24시간 이내**. 상한에 닿으면 그때까지 완성·검증한 것과 남은 일을 정리해 보고하고 멈춘다.
- **금지**
  - 유료 결제, 인터넷 외부 배포, 작업 폴더 밖 파일 수정, 시스템 전역 설정 변경
  - 실제 LLM API 유료 호출. 키가 없으므로 데모 모드로 검증한다.
  - 필요한 일은 최종 보고에서 사용자가 할 일로 안내한다.
- **허용**
  - 프로젝트 안 npm/pip 라이브러리 설치
  - 공식 문서 웹 검색(모델·가격·법정 주기 확인)
  - 하위 에이전트 병렬 작업
  - 로컬 서버 실행과 브라우저 자동화 테스트
- **실패 처리**
  - 막히는 기술 문제는 대안을 시도한다.
  - 사소한 결정은 합리적 기본값으로 정하고 docs/DECISIONS.md에 이유를 남긴 뒤 계속한다.
  - 완료 기준을 채우지 못한 단계에서는 다음 단계로 넘어가지 않는다.
- **단계 확인**: Loop 시작 전까지(PRD→TRD→Architecture→Plan→Harness→Loop 세팅)는 단계마다 결과를 보고하고 진행 여부를 확인받는다. Loop 시작이 승인되면 질문 없이 끝까지 진행한다.

## 8. 가정·리스크·미결

| 구분 | 내용 | 근거·영향 | 확인 방법 |
|---|---|---|---|
| 가정 | 법정 의무 점검 주기(방사선 장비 검사, 종사자 교육·선량, 감염관리, 소방, 개인정보 교육, 의료폐기물) | 법령 개정 가능성이 있음. 틀리면 알림이 잘못된다 | PRD/TRD 단계에서 공식 출처를 웹으로 확인하고, 불확실하면 "확인 필요"로 표시하고 사용자가 고칠 수 있게 한다 |
| 리스크 | 사진 인식 정확도·비용 | 데모 모드에서는 예시 결과만 확인할 수 있다 | 사람이 확인한 뒤 저장하는 흐름을 강제한다. 실제 정확도는 사용자가 키를 넣은 뒤 확인할 항목으로 보고한다 |
| 리스크 | 원내 AI 도우미 품질(문서 검색 방식) | 임베딩 API 없이도 동작해야 함 | TRD에서 키워드/로컬 검색 방식을 결정한다 |
| 리스크 | 범위가 크다(A~H + 추가 4개 + 확장 3개) | 24시간 상한 안에 확장을 다 못 할 수 있다 | Plan에서 MVP를 먼저 완성하고 확장은 우선순위대로 진행한다 |
| 미결 | 기술 스택, DB, 문서 검색 방식, PDF 생성 방식 | 사용자가 위임함(원문 9절) | TRD에서 결정 |

| 미결 | 디자인 시안 최종 승인 | 분위기만 합의함 | PRD 단계에서 미리보기로 확정 |
